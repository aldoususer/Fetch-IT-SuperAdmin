# Superadmin UX changes — 21 November 2026

Implemented on `codex/superadmin-ux-audit-20261121`, based on production commit
`fe68f19`. Other checkouts' unfinished edits were preserved. This branch has not
been pushed or deployed.

- Dashboard prioritizes reported platform-wide incidents and independent
  approvals, then operational exceptions, staff workload, and performance.
  The approval link applies the same ownership exclusions as its count.
- Labeled `DEMO-` bookings are excluded from performance by default. The explicit
  include control applies consistently to booking totals, fare totals, and charts.
  Account counts and operational exception queues retain their stated scopes.
- Navigation groups collapse, with the current route's group expanded initially.
  Queue controls wrap responsively and retain immediate filtering and role scopes.
- Support and application lists use compact rows with readable summaries and
  secondary metadata. Staff oversight includes issue summaries and update times.
- Opening customer messages render once when the timeline already contains the
  exact opening customer message and timestamp. No database records are deleted,
  and later repeated messages are retained.
- Customer replies and assignment/status edits are separate forms. Assignment
  edits require a before/after review. New explicit API intents reject mixed
  actions; legacy clients remain compatible. Verification, intervention reasons,
  row locking, optimistic conflicts, audit attribution, and notification delivery
  retain their existing enforcement. Drafts survive rejected writes.
- Identity verification shows its expiry and hides the redundant password form
  while fresh; expiry and identity-confirmation events update the display.
- Notification empty states link directly to unread personal alerts while keeping
  platform alerts as the owner default.
- Application cards, filters, and pipeline use the same broad stage labels.
  Detailed workflow states remain stored unchanged. Desktop review uses a section
  index and one visible section; mobile uses a selector. Deep-link hashes remain
  supported. Pending sections require an explicit decision, and unchanged saved
  decisions cannot be repeatedly submitted.
- Pricing hints show concise bounds and show the previous value only when edited.
  Included-distance edits have a 100 km ceiling; included weight is capped at the
  existing vehicle capacities: 5 kg motorcycle, 10 kg tricycle, 20 kg car. The same
  rules govern input hints and server save validation. Existing stored settings
  remain readable; prices and live configuration were not changed.
